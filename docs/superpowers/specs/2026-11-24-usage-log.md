# Usage Log and Already-Loaded Exclusion

Date: 2026-11-24
Status: Implemented; effect not measured

## Why

Every benchmark so far used model-written requests, and five attempts to
improve selection on them stalled at the same point. Other skill routers that
were reviewed (hermes-jev-skills, mu, skillranker) record whether a suggested
skill was actually loaded; one of them reports, from a replayed week of real
use, that dropping rarely loaded skills raised the share of suggestions that
were loaded from 34% to 51%. This project had no record of real use at all.

## Decision

- `usage.py` appends one JSON line per `search_skills` result and per
  `get_skill` call to `var/usage.jsonl`: timestamp, session id (one per server
  process), status, provider, suggested names and scores, and for a load
  whether that skill had been suggested in the session.
- Modes via `SKILL_RAG_USAGE_LOG`: `stats` (default, no request text), `full`
  (adds request text), `off`.
- `skill-rag usage` reports per skill: suggested, loaded after suggestion,
  loaded without suggestion.
- A skill loaded in the session is excluded from later searches in that
  session, before ranking and before any judge call
  (`SKILL_RAG_EXCLUDE_LOADED`, default on).

## Not done

No behavior depends on the statistics yet: no suppression of rarely loaded
skills, no per-skill priors, no threshold adaptation. Those need data first
and their own measurement.

## Privacy

The log stays on the machine. Request text is written only in `full` mode.
Skill names and scores are written by default; set `off` to write nothing.

## Limits

"Loaded after suggestion" is a proxy: an agent may load a skill and find it
useless, or skip a skill it should have used. The benchmark cannot measure
this change, since its requests are single-turn with no session.
